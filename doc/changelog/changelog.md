# 版本變更紀錄

本文件記錄使用者可見的行為、相容性及遷移要求。詳細實作與驗證紀錄見中文 Git 提交；發布版本與來源提交以 GitHub Release 為準。

## [Unreleased]

### Changed（變更）

- 品質報表改以 PowerShell/C# runtime 可執行行為覆蓋率門檻；CMD 功能契約與 Go 維護工具測試仍須通過。歷史報表保留原本量測範圍。

- 貢獻流程改為記錄 PR 紅燈證據、只提交綠色變更，並以 merge commit 保留歷史；維護者工作偏好獨立說明。


### Fixed（修正）

- 品質入口分頁查找同次原生與容器工件，並核對來源及摘要；ZIP 下載遇暫態錯誤時在有界時間與次數內重試。

- 修正上游清單未支援時三項 Debloat 目標被略過，並保留安裝與預佈建讀回。

- Actions 的隔離測試摘要正確顯示繁體中文與執行紀錄連結。

### Added（新增）

- Windows 測試映像提供工具回應健康檢查；測試結果仍以退出碼與報告為準。

- 維護者可選擇啟用提交訊息輔助檢查，並保留既有 hook。

- Actions 摘要顯示測試、覆蓋率及各 PowerShell 分片量測階段耗時。

- 可在主分支手動執行完整 CI，重建並驗證 Pages 品質入口及已發布的不可變最新版。

## [v0.2.5] — 2026-11-12

### Added（新增）

- Actions 執行名稱清楚標示觸發事件與來源。

- 版本發布自動封裝同次原生與容器測試報告，驗證後以單一 ZIP 保存，版本說明直接提供下載。

- 維護者可先核對不可變附件摘要，再驗證歷史報表 ZIP 及其中記載的執行脈絡。

- 維護者可將完整驗證後的報表 ZIP 原始檔與摘要輸出至專用目錄，供後續消費者核對。

- 維護工具可將同次 Windows 原生與容器的公開測試證據封裝、核對為版本專屬 ZIP，保留原始內容與容器未量測狀態。

- 新版本的 Release 說明頂端提供該版本專屬測試報表入口，方便查看對應的測試與覆蓋率證據。

### Fixed（修正）

- 修正 Audit 流程的必要資產驗證，缺少或不符的資產不再被當作可繼續執行。

- 修正 Windows Terminal 驗收對程序識別與工作階段的判斷，避免誤判其他工作階段的程序。

- 修正多顯示來源的縮放驗收，避免不同來源的縮放比例不一致時誤報通過。

- 標籤部署後驗證公開版本頁、同次來源與不可變 Release 證據，缺件、來源不符或覆蓋率未達門檻時不再回報部署驗收成功。

## [v0.2.4] — 2026-11-12

### Added（新增）

- README 提供兩條 USB 操作路徑：在地區／Wi-Fi 初始設定畫面按 Shift+F10，自動尋找 USB 後執行 Init；已有正式帳號則直接執行 Windows。保留 Ctrl+Shift+F3 稽核桌面作為可選路線，帳號建立只需一次 Init，正式帳號登入後不必重跑 Init。
- Windows 入口可自行安裝 OpenSSH Server、設定同網段防火牆並顯示連線資訊；不需先手動安裝 SSH，也不需要 agent 控制。帳號、SID、家目錄、主機名稱及工具包磁碟位置動態取得。
- 一般 Windows 電腦使用通用模組；NUC8i7HVK／HNK 驅動為可選獨立包，依板號及硬體 ID 判斷，未知型號可重新偵測或明確核對後選擇，不選包預設略過。v0.2.4 的型號獨立 ZIP 以大小、SHA256、ProfileId 及 manifest 雜湊釘選，只屬於該版本。
- 資料分享政策逐項設定及讀回；管理員提權免提示保留 UAC 啟用，提供唯讀驗證與依首份機器快照還原。首次提權仍須核准，組織政策未允許時明確回報讀回失敗。
- 報表由實際斷言與程序退出碼產生，提供 Actions 摘要、七天測試附件、Pages 簡潔報表及整體覆蓋率徽章。語言分項在報表分開計算後彙總，不以單一語言或其他提交結果代替整個儲存庫的證據；版本品質附件依來源及雜湊長期保存。
- 工作列模組預設啟用自動隱藏，沿用目前互動帳號與獨立模組入口；使用 Windows 原生 AppBar API 保留其他狀態，套用後與唯讀／重開續跑均重新讀回。沒有可用工作列或讀回失敗時停止，不影響既有 Edge 釘選、搜尋、小工具及配色設定。

### Changed（變更）

- CI 的原生完整測試與 Go 量測和 PowerShell 四片平行，最後以本次提交、執行、attempt、完整清單及原始雜湊聚合，再當地量測 C#／CMD。中介證據不可發布，正式報告仍須完整量測及兩個八成門檻通過；Docker 完整測試及原生負例保留。
- CI 工具下載局部停用原生進度並恢復偏好，解壓改用 .NET ZIP API，保留官方雜湊、重試、耗時與解壓錯誤。相同 runner 映像與工具版本的兩次冷建置分別約 29.6 與 4.0 分鐘，使用不同 fresh job；這是單次比較，不是同一實體 VM 或統計上的效能保證。完整 CI 的耗時仍以當次 Actions 為準，Windows 設定與更新的使用者進度不受影響。
- 獨立驅動包隨附完整自有 Apache-2.0 授權，保留原廠授權界線；機型說明連結依獨立包位置正確解析，發布前讀取 ZIP 核對授權及完整檔案集合，拒絕 Windows 路徑別名與檔案／目錄衝突。
- 自有程式與文件採用 Apache-2.0，根目錄附完整授權本文及 README 授權連結；第三方內容維持原有授權，不據此推定第三方二進位重新散布許可。
- Release 使用 GitHub 內建 Source code ZIP；依 README 補入並驗證 Microsoft 官方 Autologon，再將整份資料夾放上可寫入 USB。驅動包另外選擇，主程式不內嵌大型驅動、Autologon EXE、個人網路規則或每機紀錄；一般使用者不需要 Go、Git、Docker 或 agent。
- 桌面、檔案總管、解析度、配色、工作列與開始選單共用受保護的互動桌面執行流程，核對原帳號、電腦、桌面與本輪結果。工作列仍於下次登入後解除暫時政策；開始選單待套用／待登入狀態如實保留，舊版政策只在其他設定完成後明確同意才套用。
- Windows Update 顯示 API 提供的下載／安裝百分比、目前項目及最後回報時間，並保留進度 JSON 與日誌。搜尋、下載失敗或逾時明確回報，保留診斷後請求中止；不自行重新開機或關機。
- 設定、清理、hosts／SSH、更新及續跑採可單獨執行的模組與具名原流程；保留每機進度及失敗資訊，重開後可用 AfterRestart 續跑；需要只讀時可用 VerifyOnly，後者不安裝驅動或再次套用偏好。
- 維護與驗收工具以 Go 為主，原生設定保留 PowerShell 5.1；Windows runner 與離線 Windows Docker 執行單元及隔離整合測試，發布與 Pages 仍須通過對應提交的完整品質門檻。

### Fixed（修正）

- 初始設定取消後，指引在 OOBE 重新執行 Init 續問；設定包完成後才登入並執行 Windows，既有帳號與續跑紀錄保留。

- CI 收集器停用未使用的 Pester TestRegistry 暫存磁碟，移除多程序冷啟動時共用父機碼的初始化競態；保留原有測試磁碟、覆蓋率與完整測試範圍。
- Pester 的容器錯誤改用中性的 ContainerFailure 分類，避免將已執行的 BeforeAll 錯誤誤稱為探索期失敗；保留既有紀錄讀取、受限診斷欄位及隱私保護。此項僅修正診斷分類，不代表已解決另案追查的偶發量測失敗。
- 新 schema2 Tag 報告附加本次 Go 量測後可通過正式驗收；只允許合法版本、乾淨來源與同次完整成功測試，保留歷史 Release、來源／執行錯置及原始 profile 遭竄改的拒絕門檻。

- Docker 就緒入口依 PATH 優先順序只執行第一份同名程式；有多份 docker.exe 時不再把路徑串接成不存在的檔名，第一份失敗也不回退執行後方程式。

- GitHub hosted Windows 的 Docker 工作先以有界程序探測 Windows daemon；尚未就緒時最多啟動或重啟 Docker 服務一次，再以真實引擎資訊確認。超時、錯誤引擎或服務失敗仍阻擋後續容器測試，沒有降低發布門檻；一般電腦與 self-hosted runner 不會因此操作服務。

- Tag 發布前會附加同次 Go 量測與原始 profile，明確區分本機未發布 staging 與既有版本；來源、雜湊及八成門檻保持，分支與標籤兩種工作流事件皆驗證。
- 發布維護入口在原生 PowerShell `-File` 程序內可自行定位套件與預設 metadata，不受呼叫目錄影響；保留明確覆寫路徑及原有發布門檻。本機發布檢查範例從 `.version` 讀取當前版本。
- Docker 工具建置與完整測試使用各自的時間預算，避免正常測試被安裝工具所耗用的共用預算中止；以來源、工具輸入及真實映像 ID 收據鎖定後續執行，保留全部容器門檻與原生失敗退出碼。
- 完整 PowerShell 覆蓋率改由四個平行工作分攤全部安全測試，避免單一工作的時間上限中斷量測。每片保留完整來源分母，聚合重新核對本次提交、執行與重試次數，以及原生工作者的實際測試、wrapper、程序與命令證據；缺片、錯置或重用舊資料一律拒絕，整體八成門檻維持。
- 版本報表可下載同一次量測的 Go 原始覆蓋率檔，Release 品質附件以真實內容與雜湊核對後公開；歷史版本沒有原始檔時不顯示失效連結，不補造舊資料。

- Windows 前置檢查拒絕讀不到、未啟用或與目前身分不符的本機帳號；保留內建 Administrator／SYSTEM 限制，測試不再依賴 runner 的實際登入帳號。

- 修正非 UTC 時區的 mDNS 公告程序時間比較，避免正常執行的工作者被誤判失效；未來時間、過期心跳與錯誤程序仍拒絕。

- Terminal 快捷鍵支援新帳號尚未建立或註冊 Startup 目錄的情況；保留使用者原生重新導向路徑，必要時由目前帳號的 ApplicationData 解析啟動目錄，僅在套用設定時建立目錄。
- Init 在缺少或驗證失敗的設定包上，會於詢問帳密與建立帳號前停止；修正全新使用者 SSH 說明檔路徑。Windows 階段統一負責正式帳號 SSH，避免重複 Init。
- 桌面清理會移除仍可見的普通隱藏檔，保留系統檔；套件位於桌面、祖先／別名或重新解析點可能造成誤刪時先拒絕。四個系統圖示在移動前後均須完整唯一，儲存排列不接受任意四個檔案。
- 工作列 Apply 讀回搜尋、小工具、工作檢視、配置路徑、鎖定值及 Edge-only Replace XML；寫入未生效不再回報成功。登入收尾以固定受保護工作執行，舊一輪不會清掉較新的政策、RunOnce 或工作，尚未收尾也不會假通過。
- Windows Update 與 GUI 不再從可被一般使用者替換的固定公開 stage 執行程式；來源、權限、雜湊及當次身分不符時停止，舊日誌不作為本輪成功證據。
- 官方下載共用函式先確認目標路徑與暫存資料，容器建置同步保留必要來源；修正 Windows 容器環境差異及 workflow 語義驗證，失敗不能被略過或舊快取掩蓋。
- 公開入口、徽章與歷史報表核對來源提交及量測時間；部署失敗時保留上次成功報表，Release 標題僅使用版本號，不以過期附件回填新版本。
- Init 以目前原生 OOBE、帳號及桌面狀態自動檢查受控準備條件，不再要求手動輸入 AUDIT；仍須同意帳號／OOBE 變更並提供帳密。已完成的正式桌面只指向 Windows 設定；未知、矛盾或忙碌狀態在任何寫入前停止。

- 配色驗證支援自動隱藏的工作列：只在原生自動隱藏狀態與不可取樣範圍一致時記錄 AutoHidden，不喚出工作列或捏造深色像素；深色偏好、純黑背景及空白桌布仍須實際讀回。可見工作列保留 RGB 驗證，原生讀取失敗仍中止。

- 選用獨立驅動包後，逐檔顯示 SHA256 檢查的檔名、步序與實際耗時；讀取失敗或雜湊不符會指出檔案並停止，不將大型檔案的等待誤顯示為已完成。
- 自動登入階段先完成 SecureString 密碼輸入，再顯示一鍵進度面板，避免密碼提示期間被進度畫面干擾；密碼仍遮罩輸入，不新增密碼日誌。
- 清理功能不再只依 Win11Debloat 的退出碼判定成功；所選功能依目前 Windows build 逐項讀回登錄型別及值，失敗會中止並保留結果，不適用項目明列略過。唯讀驗收同樣重新檢查，避免 App 清空後掩蓋功能設定未生效。
- 驅動延伸組件支援 Windows 11 原生 `PnpUtil/Driver` XML 結構，保留精確版本、供應商與裝置關聯驗證；未知結構、無效欄位或僅存在 DriverStore 的套件仍不算已套用。
- 修正全新系統的 Code28 裝置被誤判為已載入未簽章驅動而略過安裝。只有原生問題碼、空的已安裝INF與版本／供應商／簽章資料一致時，才套用既有已核官方目標；真正未簽章、矛盾或讀取失敗仍拒絕安裝，套用後仍須正常裝置與目標版本讀回。
- 驅動解壓快取清理在乾淨程序也會載入必要的安全驗證函式，不再依賴建立快取時的區域作用域；保留本輪租約、原生程序狀態、祖先權限及重新解析點檢查，不清除不屬於本輪的資料。
- 工作列小工具從 Microsoft 官方機器政策位置讀回，修正政策已關閉卻因多讀一層 `Windows` 子路徑而誤報失敗；待下次登入的暫時配置仍單獨顯示。
- 開始選單 GPO 只在共享 Explorer 政策 key 不存在時建立，保留工作列暫時釘選配置、推薦設定及其他政策值；後置套用、重跑與工作列收尾也各自保留其他模組的設定。建立競態不再強制清空既存 key。
- SSH 階段啟動原生持續 mDNS 公告，依目前電腦名稱提供 .local 與 SSH 服務、隨網卡／DHCP 變更重綁，受保護的本機快照可在拔除 USB 後開機續用。獨立 VerifyOnly 與總驗收檢查鮮活工作者與原生註冊，不再以本機解析吻合代替公告；保留另一臺同網段電腦的連線驗證。

- Go 證據整合測試依報告的 Branch／Release 來源建立徽章，平常 PR 即執行兩種上下文；來源與 ARIA／標題變異都必須實際改變輸入並被拒絕，避免僅在版本標籤才遇到錯誤。正式來源驗證與覆蓋率門檻維持。

- 發布草稿依完整清單選定唯一版本及固定 ID，品質附件、說明與發布皆核對同一草稿；發布後驗證不可變狀態、來源及完整附件，避免草稿無法由已發布版本查詢端點讀取。

- 修正本機驗收樣本的來源身分，避免完整版本報告轉換時沿用不適用的 CI Go 證據；一般 PR 同時驗證兩種來源與兩階段報告，正式覆蓋率及發布門檻維持。

- 草稿品質附件及版本說明驗證後，更新與發布時明確保留原標籤、目標提交及版本身分，避免更新說明後標籤身分遺失；仍須完整核對來源及不可變發布證據。

## [v0.2.0] — 2026-11-07

### Changed（變更）

- Windows 主流程以通用 Windows 為預設；驅動移至獨立可攜包，只有相符 NUC 主機板且明確選包才安裝，直接 Enter 預設略過。其他機型不再因 NUC 機型檢查被阻擋。
- 版本檔、版本準備命令、PR 與 ci-rollup 統一發布流程；標籤須對應 main 歷史、版本檔與 changelog。
- RC 發布標為預覽版；正式版整合同版 RC 紀錄。使用 GitHub 內建來源下載，不再上傳重複的來源 ZIP 與 SHA256。

- 測試分為 Unit／Integration／System，CI 明示 System／E2E 未執行，避免將隔離測試當作完整安裝驗證。
- 自有目錄改小寫與底線，更新入口與路徑映射；維護工具分至 script/test、script/release、script/package，交付執行樹不依賴測試或發布工具。新驅動日誌使用 driver_logs；既有 ProgramData／排程識別及第三方原始內容保留。

- 通用流程不代表已在每種硬體完成實機驗收。現有 NUC 驅動僅提供給相符設定檔，其他硬體需使用自己的 Windows Update 或原廠驅動。
- v0.1.x 既有 Release、來源資產與標籤保持原樣。

## 初始公開版本系列（v0.1.x）

### Added（新增）

- 可選獨立驅動包改採根目錄 drivers 的資料型機種設定檔；NUC8i7HVK／HNK 依板號及精準硬體 ID 更新 12 個已核官方套件，保留必要 SWC、CAT 與完整 payload 雜湊。完成設定及重開後可唯讀重新盤點官方目標，較新版本不降版；一般電腦未選包仍略過。


- Init 提供本機帳號及 SSH 初始化；Windows 入口依模組執行設定，支援重新開機後續跑及只讀驗收。
- 提供自動登入、電源、分頁檔、更新、預裝 App／OneDrive 清理、工作列、桌面、深色背景、英文美式鍵盤與 Terminal 快捷鍵模組。
- SSH 與 hosts 可獨立同步，站點規則由目前使用者動態維護；公開範本不包含私人主機清單或金鑰。
- Windows CI 執行語法與隔離測試；版本標籤通過測試後發布來源 ZIP 與 SHA256。CI 報告短期保存，實機續跑紀錄留在原機。

### Changed（變更）

- 對外產品名稱為 Windows 設定工具，儲存庫為 windows_setup；發布包採 windows_setup_vX.Y.Z_source.zip，根目錄 windows_setup/。
- 完整工具包可整包搬移到可寫入且非桌面的路徑，動態取得帳號與工具包位置，不固定使用者名稱或磁碟代號。
- 目前 Windows 一鍵硬體設定檔與內建驅動仍限定 NUC8i7HV/HN；其他硬體並未因改名而自動支援。既有 ProgramData 與續跑識別保留。

### Security（資料保護）

- Git 與來源發布包排除帳號暫存、私鑰、個人網路規則、每機紀錄及安裝二進位；完整包仍須自行補齊可信來源的 Autologon 與驅動並通過檢查。

### 驗證界限

雲端測試驗證來源與隔離邏輯，不能代替新電腦的 OOBE、更新、驅動、登入與顯示驗收。Windows 版本與硬體差異可能影響結果。
